1. Gambaran Umum Sistem

Website BisaGym adalah sistem manajemen gym berbasis web yang dirancang untuk membantu pengelolaan operasional pusat kebugaran secara terpadu dan efisien. Sistem ini mencakup berbagai aspek manajemen gym, mulai dari pendaftaran anggota, pencatatan kehadiran, pembayaran, pengelolaan karyawan, hingga laporan keuangan. Keunggulan utama sistem ini terletak pada integrasi teknologi kecerdasan buatan (AI) biometrik pengenalan wajah yang memungkinkan pencatatan kehadiran anggota secara otomatis tanpa memerlukan kartu fisik atau input manual.

Sistem dibangun di atas dua lapisan aplikasi yang saling terintegrasi. Lapisan pertama adalah aplikasi web utama yang dikembangkan menggunakan framework Laravel 11 berbasis PHP 8.3, berfungsi sebagai antarmuka bisnis utama yang menangani seluruh logika manajemen gym dan interaksi pengguna. Lapisan kedua adalah layanan API biometrik yang dikembangkan menggunakan FastAPI berbasis Python 3.13, berfungsi sebagai mesin kecerdasan buatan yang memproses deteksi dan pengenalan wajah menggunakan model deep learning YuNet dan SFace dari OpenCV.

Dengan arsitektur dua lapisan ini, Website BisaGym mampu menawarkan pengalaman pengguna yang lengkap: staf dapat mengelola seluruh operasional gym melalui antarmuka web yang intuitif, sementara di balik layar sistem AI bekerja secara otomatis untuk memverifikasi identitas anggota berdasarkan ciri biometrik wajah mereka.

2. Arsitektur Aplikasi

Arsitektur Website BisaGym menggunakan pendekatan microservice ringan, di mana aplikasi web utama (Laravel) dan layanan AI biometrik (FastAPI) berjalan sebagai proses terpisah namun berkomunikasi melalui protokol HTTP internal.

2.1 Lapisan Aplikasi Web (Laravel)

Aplikasi Laravel berjalan pada port 8000 dan merupakan titik masuk utama seluruh pengguna sistem. Aplikasi ini mengelola database MySQL yang menyimpan data bisnis seperti informasi anggota, transaksi, keuangan, dan data karyawan. Laravel menggunakan pola arsitektur MVC (Model–View–Controller) di mana setiap fitur dikelola oleh kelas Controller tersendiri, data direpresentasikan oleh kelas Model Eloquent, dan tampilan dirender menggunakan template engine Blade yang dikombinasikan dengan Tailwind CSS untuk menghasilkan antarmuka yang responsif dan modern.

2.2 Lapisan API Biometrik (FastAPI + Python)

Layanan API biometrik berjalan pada port 8001 di dalam direktori Website-BisaGym/bisagym-api/. Layanan ini menggunakan model deep learning berbasis ONNX yang dijalankan melalui OpenCV 4.13: model YuNet untuk deteksi wajah dan model SFace untuk ekstraksi ciri wajah (face embedding). Data biometrik disimpan dalam database SQLite terpisah (gym.db) untuk menjaga isolasi antara data bisnis dan data biometrik yang sensitif.

2.3 Komunikasi Antar Lapisan

Komunikasi antara Laravel dan FastAPI dilakukan melalui kelas layanan FaceRecognitionApi.php yang berperan sebagai wrapper atau adaptor. Setiap kali fitur yang berkaitan dengan biometrik dipanggil oleh pengguna melalui antarmuka web, kelas ini akan menerjemahkan permintaan tersebut menjadi panggilan HTTP ke API Python, mengirimkan data gambar dalam format Base64, menerima respons JSON, dan meneruskan hasilnya ke Controller Laravel yang memanggilnya. Mekanisme autentikasi antara Laravel dan FastAPI menggunakan token JWT yang dikelola secara internal.

Ringkasan teknologi yang digunakan:
  • Web Framework: Laravel 11 (PHP 8.3) — routing, MVC, autentikasi, ORM Eloquent
  • AI Framework: FastAPI (Python 3.13) + OpenCV 4.13 — deteksi dan pengenalan wajah
  • Model AI: YuNet (deteksi) + SFace (pengenalan) dalam format ONNX
  • Database Bisnis: MySQL — member, transaksi, keuangan, karyawan
  • Database Biometrik: SQLite (gym.db) — vektor wajah terenkripsi
  • Frontend: Blade Templating + Tailwind CSS
  • Autentikasi Web: Laravel Breeze (session-based)

3. Alur Autentikasi dan Hak Akses Pengguna

Setiap pengguna yang ingin mengakses sistem diwajibkan untuk masuk (login) terlebih dahulu. Ketika pengguna membuka alamat utama sistem melalui browser, sistem secara otomatis mengalihkan ke halaman login (/login). Pengguna memasukkan alamat email dan kata sandi yang telah terdaftar dalam database sistem.

Sistem kemudian memvalidasi kredensial tersebut melalui AuthController. Apabila email atau kata sandi tidak sesuai, sistem akan menampilkan pesan kesalahan dan pengguna diminta memasukkan ulang datanya. Apabila kredensial valid, sistem membuat sesi (session) yang aman untuk pengguna tersebut dan mengalihkannya ke halaman dasbor (/dashboard).

Website BisaGym menerapkan sistem kontrol akses berbasis peran (Role-Based Access Control / RBAC) melalui mekanisme middleware Laravel. Setiap pengguna memiliki peran yang menentukan menu dan fitur apa saja yang dapat diaksesnya:

  • Developer — memiliki akses penuh ke seluruh fitur sistem, termasuk manajemen akun pengguna, penghapusan transaksi, dan log aktivitas sistem.
  • Admin — dapat mengelola seluruh operasional gym seperti manajemen anggota, karyawan, paket keanggotaan, diskon, dan laporan keuangan.
  • Kasir — memiliki akses ke fitur kasir, point of sale snack, laporan shift, dan pengeluaran.
  • Penjaga — dapat mengakses fitur absensi anggota, streaming kamera, dan manajemen perangkat kiosk.

Setiap rute yang memerlukan autentikasi dilindungi oleh middleware auth, sementara rute yang memerlukan peran tertentu dilindungi oleh middleware role:nama_peran. Apabila pengguna mencoba mengakses rute yang tidak sesuai dengan perannya, sistem akan menolak akses dan menampilkan halaman kesalahan 403.

4. Alur Pendaftaran Member

Sistem menyediakan dua jalur pendaftaran anggota gym, yaitu pendaftaran mandiri oleh calon anggota melalui halaman publik dan pendaftaran yang dilakukan oleh staf gym melalui panel administrasi.

4.1 Pendaftaran Mandiri oleh Calon Anggota (Publik)

Calon anggota dapat mendaftarkan diri secara mandiri melalui halaman /pendaftaran tanpa perlu masuk ke sistem. Halaman ini dikelola oleh PublicRegistrationController dan menampilkan formulir yang meminta data pribadi calon anggota seperti nama lengkap, alamat email, nomor telepon, dan foto identitas. Setelah formulir dikirimkan, sistem menyimpan data tersebut ke dalam database dengan status keanggotaan pending (menunggu verifikasi). Staf gym kemudian akan memverifikasi data dan mengaktifkan keanggotaan melalui panel administrasi.

4.2 Pendaftaran oleh Staf Gym

Staf gym yang telah masuk ke sistem dapat mendaftarkan anggota baru melalui menu Anggota (/members/create). Proses ini dikelola oleh MemberController. Staf memasukkan data lengkap anggota, memilih paket keanggotaan yang diinginkan, mengunggah foto anggota, dan menentukan tanggal mulai keanggotaan. Sistem kemudian membuat catatan anggota baru beserta transaksi pembayaran yang menunggu pelunasan.

Proses pembayaran dilanjutkan melalui menu Kasir. Kasir membuka halaman /cashier/member, mencari anggota berdasarkan nama atau ID, memilih transaksi yang menunggu pembayaran, memasukkan jumlah uang yang diterima, dan menyelesaikan pembayaran. Setelah pembayaran dikonfirmasi, status keanggotaan anggota otomatis diubah menjadi aktif dan sistem menghasilkan kartu anggota elektronik (e-card) yang dapat diakses melalui /members/{id}/ecard.

4.3 Perpanjangan Keanggotaan

Anggota yang masa keanggotaannya akan habis atau telah habis dapat memperpanjang melalui menu Anggota. Staf membuka detail anggota yang bersangkutan, memilih menu perpanjangan (renewal), menentukan paket baru yang diinginkan, dan membuat transaksi perpanjangan. Proses pembayaran dilakukan dengan cara yang sama seperti pendaftaran baru melalui menu Kasir. Setelah lunas, tanggal berakhir keanggotaan secara otomatis diperbarui sesuai durasi paket yang dipilih.

5. Alur Pencatatan Absensi Member

Pencatatan kehadiran anggota gym dapat dilakukan melalui dua mode yang tersedia pada halaman Scan Absensi (/attendance), yaitu mode pemindaian ID secara manual dan mode kiosk wajah berbasis kecerdasan buatan.

5.1 Mode Pemindaian ID (Manual)

Pada mode ini, staf penjaga membuka tab "Scan ID" pada halaman absensi. Anggota gym menyerahkan kartu anggota mereka untuk dipindai menggunakan pemindai barcode, atau staf dapat mengetikkan ID anggota secara manual pada kolom pencarian yang tersedia. Setelah ID dikirimkan melalui formulir (POST /attendance), sistem melalui AttendanceController@store akan mencari data anggota di database, memeriksa apakah keanggotaan masih aktif dan belum melewati tanggal berakhir, serta mencatat kehadiran ke tabel member_attendances dengan timestamp saat itu. Apabila keanggotaan tidak aktif atau telah kedaluwarsa, sistem menampilkan notifikasi peringatan kepada staf.

5.2 Mode Kiosk Wajah AI (Otomatis)

Mode ini memungkinkan pencatatan absensi dilakukan secara mandiri oleh anggota hanya dengan berdiri di depan kamera tanpa memerlukan bantuan staf. Ketika tab "Kiosk Wajah AI" diaktifkan, tampilan beralih ke mode layar penuh (fullscreen) yang menampilkan umpan video kamera secara langsung. Sistem secara otomatis mengirimkan frame video ke server setiap dua detik dalam format gambar Base64 melalui permintaan AJAX ke POST /attendance/face-checkin.

Permintaan ini diterima oleh AttendanceController@faceCheckin yang selanjutnya meneruskan data gambar ke layanan API biometrik melalui kelas FaceRecognitionApi. API biometrik pada port 8001 memproses gambar menggunakan model YuNet untuk mendeteksi keberadaan wajah dalam gambar, kemudian menggunakan model SFace untuk mengekstrak vektor ciri wajah (face embedding) berukuran 128 dimensi. Vektor ini dibandingkan dengan seluruh data vektor wajah anggota yang telah terdaftar sebelumnya menggunakan metrik cosine similarity. Apabila tingkat kemiripan melebihi ambang batas yang ditentukan, sistem mengidentifikasi anggota yang bersangkutan dan mengembalikan ID anggota tersebut ke Laravel.

Setelah identitas anggota berhasil diverifikasi, Laravel mencatat kehadiran anggota tersebut secara otomatis ke database. Antarmuka kiosk menampilkan nama anggota beserta pesan selamat datang, membunyikan umpan balik audio, dan mereset tampilan untuk siap menerima anggota berikutnya. Seluruh proses berlangsung dalam waktu kurang dari tiga detik.

6. Alur Pendaftaran Wajah (Face Enrollment) dengan AI

Sebelum seorang anggota dapat menggunakan fitur kiosk wajah AI untuk absensi, wajah anggota tersebut harus terlebih dahulu didaftarkan ke dalam sistem melalui proses face enrollment. Proses ini dilakukan oleh staf melalui menu Pendaftaran Wajah (/face-enrollment) dan terdiri dari empat tahapan utama.

6.1 Pemilihan Anggota

Staf membuka halaman pendaftaran wajah yang dikelola oleh FaceEnrollmentController@index. Halaman ini menampilkan daftar seluruh anggota gym beserta status pendaftaran wajah mereka, apakah sudah terdaftar, belum terdaftar, atau sedang dalam proses pendaftaran. Staf memilih anggota yang ingin didaftarkan wajahnya dengan mengklik tombol yang tersedia.

6.2 Inisiasi Sesi Pendaftaran

Setelah anggota dipilih, staf memulai sesi pendaftaran dengan mengirimkan permintaan ke POST /face-enrollment/{member}/start. FaceEnrollmentController@start meneruskan permintaan ini ke API biometrik melalui FaceRecognitionApi. API biometrik membuat sesi pendaftaran baru dan mengembalikan token sesi unik (enrollment_token) yang berfungsi sebagai penanda sesi pendaftaran yang sedang berlangsung. Token ini disimpan sementara untuk digunakan pada tahap pengambilan sampel berikutnya.

6.3 Pengambilan Sampel Foto Wajah

Tahapan inti dari proses pendaftaran adalah pengambilan tiga sampel foto wajah anggota dengan pose yang berbeda. Antarmuka menampilkan panduan berupa bingkai oval di layar kamera untuk membantu anggota memposisikan wajah dengan tepat. Ketiga pose yang diperlukan adalah: pose menghadap lurus ke depan (frontal), pose sedikit menoleh ke kiri, dan pose sedikit menoleh ke kanan.

Untuk setiap pose, staf atau anggota menekan tombol pengambilan gambar. Gambar diambil dari umpan kamera, dikonversi ke format Base64, dan dikirimkan ke POST /face-enrollment/{member}/samples bersama dengan token sesi yang diperoleh pada tahap sebelumnya. API biometrik kemudian menjalankan serangkaian pemeriksaan kualitas gambar sebelum menerimanya sebagai sampel yang valid.

Pemeriksaan kualitas yang dilakukan oleh API biometrik meliputi: verifikasi bahwa setidaknya satu wajah terdeteksi dalam gambar (NO_FACE), pemeriksaan bahwa wajah tidak terlalu kecil atau terlalu jauh dari kamera (FACE_TOO_SMALL), analisis ketajaman gambar untuk memastikan tidak buram (IMAGE_TOO_BLURRY), evaluasi pencahayaan untuk memastikan tidak terlalu gelap atau terlalu terang (BAD_EXPOSURE), serta deteksi bahwa hanya ada satu wajah dalam frame (MULTIPLE_FACES). Jika gambar tidak memenuhi standar kualitas, sistem menampilkan pesan kesalahan dalam bahasa Indonesia yang informatif dan meminta pengambilan ulang untuk pose tersebut.

6.4 Penyelesaian Pendaftaran

Setelah ketiga sampel berhasil dikumpulkan, staf menekan tombol selesai yang mengirimkan permintaan ke POST /face-enrollment/{member}/complete. API biometrik kemudian memproses ketiga sampel tersebut: mengekstrak vektor ciri wajah (face embedding) berukuran 128 dimensi dari setiap sampel menggunakan model SFace, dan menyimpan rata-rata atau representasi terbaik dari ketiga vektor tersebut ke dalam database SQLite gym.db yang terenkripsi. Mulai saat ini, anggota tersebut dapat menggunakan kiosk wajah AI untuk absensi.

6.5 Penghapusan Data Wajah

Staf dengan wewenang yang sesuai dapat menghapus data biometrik seorang anggota kapan saja melalui tombol Hapus Data Wajah pada halaman pendaftaran wajah. Permintaan ini dikirimkan ke POST /face-enrollment/{member}/revoke yang akan menghapus seluruh data vektor wajah anggota dari database SQLite. Setelah penghapusan, anggota tersebut tidak dapat lagi menggunakan fitur kiosk wajah AI hingga wajahnya didaftarkan kembali.

7. Alur Kasir dan Pembayaran Transaksi

Fitur kasir pada Website BisaGym dirancang untuk memproses pembayaran transaksi anggota gym, baik untuk pendaftaran keanggotaan baru maupun perpanjangan. Fitur ini dikelola oleh CashierController dan dapat diakses melalui menu Kasir (/cashier/member).

Proses pembayaran dimulai dengan kasir membuka halaman kasir dan mencari anggota yang akan membayar. Pencarian dapat dilakukan berdasarkan nama, nomor anggota, atau nomor telepon. Setelah anggota ditemukan, sistem menampilkan daftar transaksi milik anggota tersebut yang masih menunggu pembayaran beserta detail paket keanggotaan dan jumlah yang harus dibayar.

Kasir memilih transaksi yang akan dibayar, memasukkan jumlah uang yang diterima dari anggota, dan memilih metode pembayaran (tunai atau transfer bank). Sistem secara otomatis menghitung jumlah kembalian apabila uang yang diterima melebihi jumlah tagihan. Kasir kemudian mengkonfirmasi pembayaran dengan mengirimkan formulir ke POST /cashier/pay/{transaction}.

Setelah pembayaran dikonfirmasi, sistem mencatat transaksi sebagai lunas, memperbarui status keanggotaan anggota menjadi aktif, menetapkan tanggal mulai dan tanggal berakhir keanggotaan sesuai paket yang dipilih, dan mencatat seluruh aktivitas ini ke dalam log sistem. Kasir juga dapat memproses pembayaran untuk kunjungan non-anggota melalui menu Bayar Non-Anggota (POST /cashier/pay-non-member).

Sistem diskon dapat diterapkan secara otomatis pada saat transaksi apabila anggota memenuhi syarat diskon yang telah dikonfigurasi sebelumnya oleh admin melalui menu Diskon (/discounts). Diskon dapat berupa persentase dari total tagihan atau potongan nominal tertentu.

8. Alur Point of Sale (POS) Snack

Fitur Point of Sale (POS) Snack dirancang untuk memproses penjualan produk makanan dan minuman yang tersedia di gym. Fitur ini dikelola oleh PosController dan dapat diakses melalui menu POS (/pos).

Kasir atau penjaga membuka halaman POS yang menampilkan katalog seluruh produk snack yang tersedia beserta stok dan harga masing-masing. Kasir memilih produk yang dibeli pelanggan dan menentukan jumlahnya. Setiap produk yang dipilih secara otomatis ditambahkan ke keranjang belanja virtual yang menampilkan ringkasan pesanan beserta total harga secara real-time.

Setelah pemilihan produk selesai, kasir memproses pembayaran dengan mengirimkan pesanan ke POST /pos/checkout. Sistem melalui PosController@checkout akan membuat catatan transaksi snack baru (SnackTransaction), mencatat detail setiap item yang dibeli (SnackTransactionDetail), dan mengurangi stok produk yang terjual dari inventori secara otomatis. Apabila stok suatu produk tidak mencukupi, sistem akan memberikan peringatan sebelum transaksi diproses.

Manajemen inventori snack dilakukan secara terpisah melalui menu Snack (/snacks). Staf dapat menambahkan stok masuk melalui POST /snacks/incoming dan melakukan pengisian ulang kulkas display melalui POST /snacks/refill-kulkas. Seluruh pergerakan stok dicatat secara otomatis dalam model SnackRestock untuk keperluan audit.

9. Alur Laporan Keuangan dan Shift

9.1 Laporan Transaksi

Seluruh transaksi yang terjadi dalam sistem dapat dipantau melalui menu Laporan Transaksi (/transactions) yang dikelola oleh TransactionController. Halaman ini menampilkan daftar seluruh transaksi dengan fitur penyaringan berdasarkan rentang tanggal, jenis transaksi, dan status pembayaran. Pengguna dengan peran admin atau developer dapat mengekspor data transaksi ke dalam format Excel melalui GET /transactions/export. Khusus pengguna dengan peran developer, tersedia pula fitur untuk mengedit atau menghapus transaksi apabila terjadi kesalahan pencatatan.

9.2 Laporan Keuangan

Laporan keuangan yang lebih komprehensif tersedia melalui menu Laporan Keuangan (/financial-report) yang dikelola oleh FinancialReportController. Halaman ini menyajikan ringkasan pemasukan dari transaksi anggota dan penjualan snack, dikurangi dengan total pengeluaran operasional, sehingga menghasilkan gambaran laba atau rugi dalam periode tertentu. Pengeluaran operasional seperti biaya listrik, air, peralatan, dan lainnya dapat dicatat melalui menu Pengeluaran (/expenses).

9.3 Laporan Shift

Setiap kasir yang bertugas dapat membuka dan menutup shift kerjanya melalui menu Laporan Shift (/shift-reports) yang dikelola oleh ShiftReportController. Pada saat menutup shift, kasir menyerahkan rekap transaksi yang terjadi selama shift tersebut berlangsung. Sistem menyimpan data rekonsiliasi shift ini dalam model ShiftReconciliation yang dapat diperiksa oleh supervisor atau admin untuk keperluan audit kas.

10. Alur Manajemen Karyawan

Fitur manajemen karyawan menyediakan sistem yang terintegrasi untuk mengelola data seluruh karyawan gym, termasuk jadwal kerja, pencatatan kehadiran, dan penggajian. Fitur ini hanya dapat diakses oleh pengguna dengan peran admin atau developer.

10.1 Data Karyawan

Admin dapat mengelola data karyawan melalui menu Karyawan (/employees) yang dikelola oleh EmployeeController. Fitur CRUD (Create, Read, Update, Delete) tersedia untuk menambah karyawan baru, melihat dan mengubah data karyawan, serta menonaktifkan karyawan yang sudah tidak bekerja.

10.2 Jadwal Shift Karyawan

Jadwal kerja setiap karyawan dikelola melalui EmployeeShiftController. Admin dapat menetapkan jadwal shift kerja untuk setiap karyawan melalui halaman /employees/{id}/shifts. Jadwal ini mencatat hari kerja, jam masuk, dan jam pulang yang diharapkan untuk setiap karyawan.

10.3 Absensi Karyawan

Kehadiran karyawan dicatat secara manual oleh admin melalui menu Absensi Karyawan (/employee-attendances) yang dikelola oleh EmployeeAttendanceController. Admin memasukkan data kehadiran setiap karyawan termasuk jam masuk, jam keluar, dan keterangan apabila ada ketidakhadiran.

10.4 Penggajian

Sistem penggajian dikelola melalui EmployeePayrollController. Admin dapat membuat catatan penggajian untuk setiap karyawan berdasarkan periode tertentu melalui /employees/{id}/payrolls. Catatan ini mencakup jumlah gaji pokok, tunjangan, potongan, dan jumlah bersih yang dibayarkan.

10.5 Informasi Pribadi Karyawan

Setiap karyawan yang memiliki akun di sistem dapat melihat informasi pekerjaan mereka sendiri melalui menu Informasi Saya (/my-employee-info). Halaman ini menampilkan jadwal shift aktif, riwayat absensi, dan riwayat penggajian milik karyawan yang sedang login.

11. Alur Streaming Kamera dan Deteksi Wajah Real-time

Fitur streaming kamera memungkinkan pengguna untuk memantau area gym secara langsung melalui browser dengan kemampuan deteksi wajah real-time. Fitur ini dikelola oleh StreamingCameraController dan dapat diakses melalui menu Streaming Kamera (/streaming) oleh seluruh pengguna yang telah masuk ke sistem.

Ketika halaman streaming dibuka, browser meminta izin akses kamera kepada pengguna. Setelah izin diberikan, umpan video dari kamera ditampilkan secara langsung pada elemen video di halaman. Secara bersamaan, sistem mulai mengambil frame dari video secara periodik setiap 500 milidetik, mengonversinya ke format gambar Base64, dan mengirimkannya ke server melalui permintaan AJAX ke POST /streaming/analyze.

Server melalui StreamingCameraController@analyze meneruskan gambar ke API biometrik untuk diproses menggunakan model YuNet. API mengembalikan koordinat bounding box dari setiap wajah yang terdeteksi dalam gambar beserta informasi identitas apabila wajah tersebut cocok dengan data anggota yang terdaftar. Informasi ini dikirimkan kembali ke browser dalam format JSON.

Browser menerima respons JSON dan menggambar kotak pembatas (bounding box) di atas wajah yang terdeteksi menggunakan elemen canvas HTML yang dilapisi di atas video. Apabila wajah yang terdeteksi berhasil diidentifikasi sebagai anggota terdaftar, nama anggota tersebut ditampilkan di atas kotak pembatas. Algoritma IoU (Intersection over Union) digunakan untuk melacak konsistensi posisi wajah antar frame sehingga kotak pembatas tidak bergetar secara berlebihan.

12. Alur Manajemen Perangkat Kiosk

Fitur manajemen perangkat memungkinkan administrator untuk mendaftarkan dan mengelola perangkat kiosk fisik yang dipasang di lokasi gym untuk keperluan absensi mandiri anggota. Fitur ini dikelola oleh DeviceController dan dapat diakses melalui menu Perangkat (/devices).

Halaman ini menampilkan daftar seluruh perangkat kiosk yang telah terdaftar dalam sistem, lengkap dengan nama perangkat, status aktif atau nonaktif, dan informasi kredensial API yang digunakan oleh perangkat tersebut untuk berkomunikasi dengan layanan biometrik. Data perangkat diambil secara langsung dari API biometrik melalui FaceRecognitionApi dan disinkronkan saat halaman dimuat atau ketika pengguna menekan tombol refresh (GET /devices/refresh).

Administrator dapat mendaftarkan perangkat kiosk baru melalui formulir yang tersedia dengan mengisi nama perangkat dan informasi lokasinya, kemudian mengirimkan data ke POST /devices. Sistem API biometrik akan menghasilkan pasangan kunci API (API key) yang unik untuk perangkat tersebut yang digunakan sebagai identitas perangkat saat berkomunikasi dengan server.

Perangkat yang sudah terdaftar dapat diaktifkan atau dinonaktifkan sewaktu-waktu melalui tombol Toggle yang mengirimkan permintaan ke PATCH /devices/{deviceId}/toggle. Apabila kredensial API perangkat perlu diperbarui karena alasan keamanan, administrator dapat memutar ulang (rotate) kunci API melalui POST /devices/{deviceId}/rotate-credential yang akan menghasilkan pasangan kunci baru dan membatalkan kunci lama secara otomatis.

13. Struktur Database

13.1 Database Bisnis (MySQL)

Database MySQL menjadi pusat penyimpanan seluruh data bisnis operasional gym. Tabel-tabel utama dan fungsinya adalah sebagai berikut:

  • users — menyimpan data akun pengguna sistem beserta peran masing-masing (developer, admin, kasir, penjaga).
  • members — menyimpan data anggota gym termasuk informasi pribadi, foto, dan status keanggotaan.
  • gym_packages — menyimpan konfigurasi paket keanggotaan dengan durasi dan harga masing-masing.
  • member_transactions — mencatat setiap transaksi keanggotaan beserta status pembayaran dan tanggal berlaku.
  • member_attendances — menyimpan log kehadiran setiap anggota beserta metode absensi yang digunakan.
  • discounts — menyimpan data diskon yang dapat diterapkan pada transaksi.
  • employees — menyimpan data karyawan gym.
  • employee_shifts — menyimpan jadwal shift kerja setiap karyawan.
  • employee_attendances — mencatat kehadiran karyawan setiap hari.
  • employee_payrolls — menyimpan catatan penggajian karyawan per periode.
  • snacks — menyimpan daftar produk snack beserta harga dan stok saat ini.
  • snack_transactions — mencatat setiap transaksi penjualan snack.
  • snack_transaction_details — menyimpan detail item per transaksi snack.
  • snack_restocks — mencatat setiap penambahan stok snack.
  • expenses — menyimpan catatan pengeluaran operasional gym.
  • shift_reconciliations — menyimpan data rekonsiliasi pada saat penutupan shift kasir.
  • activity_logs — mencatat seluruh aktivitas signifikan yang dilakukan pengguna dalam sistem.

13.2 Database Biometrik (SQLite — gym.db)

Database SQLite digunakan secara terpisah khusus untuk menyimpan data biometrik yang sensitif. Pemisahan ini bertujuan untuk meningkatkan keamanan data wajah anggota agar tidak tercampur dengan data bisnis umum. Tabel-tabel utama dalam database ini meliputi:

  • users — akun internal API biometrik (superadmin, admin, reception) yang digunakan untuk autentikasi antara Laravel dan FastAPI.
  • branches — data cabang gym yang terdaftar (kode cabang dan nama cabang).
  • members — referensi ID anggota yang memiliki data biometrik terdaftar.
  • face_enrollments — token sesi pendaftaran wajah yang sedang aktif.
  • face_samples — vektor ciri wajah (face embedding) berukuran 128 dimensi hasil ekstraksi model SFace untuk setiap anggota.
  • devices — daftar perangkat kiosk yang terdaftar beserta kunci API dan status aktivasinya.
